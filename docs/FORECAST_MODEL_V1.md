# Прогноз продолжения процесса v1

Реализация пункта D первого разработчика строит прогноз серы ПАК ровно через 60 минут при
сохранении настроек. Это наблюдательный continuation forecast, а не доказательство эффекта
управляющего действия. Непустые `Action.changes` остаются `unsupported` до отдельного пункта E.

## Воспроизведение

```sh
uv run neftecode-hackathon prepare
uv run neftecode-hackathon train
```

Вторая команда читает только `data/processed/`, создаёт Git-ignored `artifacts/model.joblib`,
`manifest.json`, `metrics.json`, `model_report.md` и печатает выбранный predictor с validation/test
MAE. Конфигурация, seed, признаки, split и гиперпараметры находятся в `config/model.yaml`.
Artifact и runtime-конфигурация связаны SHA-256; несовпадение версий вызывает явную ошибку.

## Target и признаки

Target — valid `pak:ht.product_sulfur` в `mg/kg` на точном timestamp `t+60 минут`.
Интерполяции будущей цели нет. Из 189 649 уникальных корректных значений 189 643 имеют точную
цель; шесть последних origins исключены с подсчётом.

Набор признаков зафиксирован до чтения final test и использует источники с подтверждёнными
единицами:

- ПАК сера продукта и ПАК D15: current, age, лаги 10/60/360 минут, средние 60/360 минут,
  изменение за 60 минут;
- последнее доступное ЛИМС-значение серы сырья точки 1 (`% mass`) и серы продукта точки 2
  (`mg/kg`) вместе с возрастом;
- ЛИМС попадает в признаки только при `available_at <= t` с консервативной задержкой 240 минут
  и freshness 48 часов.

P8/T11/F19 сознательно не включены: их связь с оборудованием подтверждена, но численные единицы
и шкалы нет. Это не мешает прогнозу продолжения по качеству и не создаёт ложную поддержку
действий. Один `ForecastFeatureBuilder` формирует одинаковые имена и значения для train/serving;
тест сравнивает обе стороны на одном point-in-time примере.

## Разбиение и модель

Точные пары origin/target делятся по времени 70/15/15. Origins конца train и validation удаляются,
если их target достигает следующего сегмента: удалено по шесть строк на каждой границе. Итог:

- train: 132 744;
- validation: 28 440;
- untouched test: 28 447.

`HistGradientBoostingRegressor` обучается только на train с параметрами handoff: squared error,
200 итераций, 15 листьев, learning rate 0.05, L2 1.0, early stopping выключен, seed 42.
Imputer/scaler не используются; HGB обрабатывает пропуски непосредственно. Выбор predictor и
90%-квантиль абсолютных residuals выполняются только на validation. Final test не используется
для выбора признаков, модели, параметров или интервала.

## Фактический результат

Model version:
`forecast-v1:9ade91386ad0311b3e3e60b061d34ffafd1cde188e32a268fb29c1f6b986fa0a`.

| Метрика | HGB | Persistence baseline |
| --- | ---: | ---: |
| Validation MAE, мг/кг | 0.621067 | 0.573082 |
| Test MAE, мг/кг | 1.184255 | 0.706412 |

HGB проиграл на validation, поэтому выбран `persistence_baseline`: последнее доступное корректное
значение ПАК. Это не модель эффекта действия. Радиус empirical interval — 1.219977 мг/кг, нижняя
граница ограничивается нулём. Validation coverage — 0.900035, test coverage — 0.819032: номинал
0.90 не подтвердился на test, поэтому `minimum_interval_coverage` в общей policy остаётся `null`,
а снижать его по final test запрещено.

На test 4 596 превышений серы >10 и 23 851 нормальная точка. Alert определяется как верхняя
граница интервала >10: пропущено 437 превышений (9.51%), ложных тревог 6 260 (26.25%). При
нулевом знаменателе соответствующая доля сериализуется как `null`, не 0.

Отдельная сверка с ЛИМС продукта строит состояние за 60 минут до времени отбора и использует
лабораторное значение только как последующий label: 217 test-сопоставлений, MAE 1.676522 мг/кг,
coverage 0.552995. Это существенно слабее сверки по ПАК и явно показывается, а не скрывается.

## Serving и ограничения

`ForecastQualityAgent.from_repository()` загружает artifact один раз, проверяет model/config/data
version и feature schema. Он выдаёт числа только для 60 минут, пустого action, совпадающей версии
данных и replay не раньше test boundary `2026-01-24T07:00:00Z`. Обязательный вход manifest —
свежая valid ПАК-сера в `mg/kg`, возраст не более 1200 секунд.

Общая scenario policy получила verified manifest, но остаётся fail-closed:

- `minimum_interval_coverage=null`, потому что nominal coverage не выдержан на test;
- `hard_check_inventory_verified=false`;
- P8/T11/F19 `available=false`, пока нет единиц/шкал, train-only диапазонов, шага и action support;
- будущие выпуск/стоимость и безопасность перехода не оценены.

Поэтому реальный baseline уже получает поддерживаемый прогноз качества, но весь
`ScenarioEvaluation` пока `not_assessable`. Это ожидаемый промежуточный результат, не готовая
рекомендация оператору.
